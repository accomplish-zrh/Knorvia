# 从资料到作品

使用当前会话模型创作，`creative_brief` 负责校验、保存和读取版本。先查阅当前工具描述获取参数，不启动额外的代理循环。

## 明确作品

从用户已提供的材料和要求提取受众、希望读者理解或采取的行动、作品形式与交付要求。可以根据上下文选择合理默认值，不为已明确的要求重复询问。简单润色不必建立简报。

通过资料库工具读取选定来源及其版本。将作品中的事实主张与原文行号和引用对应；推断、虚构情节和表达建议与有来源的事实区分。`creative_brief create` 会核对实际原文，引用不匹配时应修正引用或删除无依据主张，不可为通过校验而修改源资料。

把完成条件写成能逐项检查的要求，例如：包含三个指定知识点、给出面向新手的例子、每个镜头有时长与画面说明。可用 `learningRefs` 关联已存在的学习成果；关联练习或完成材料阅读不代表用户已经掌握。

## 产出与评审

创作并把实际作品保存到资料库，随后读取保存结果。简报本身和参考资料不能充当最终作品。用 `creative_brief review` 关联实际成果版本，逐项提交评审结果和理由，评审者注明 `agent`；只有用户实际给出评审时才用 `user`。

未检查的条件标为 `not-checked`，需要修改的条件标为 `needs-work`。工具检验文件与记录，内容质量仍来自所注明的评审者判断。评审通过后再读一次简报，确认来源、作品与状态，并向用户交付真实路径。

作品或来源后来更新，需要针对新版本复核。创建和评审重试复用原 `requestId` / `reviewId` 与原参数；需求或评审内容改变时使用新编号。记录写入失败时保留已生成作品，报告未保存的步骤，不声称已完成评审。

视频、幻灯片等任务可以按用户要求继续调用当前可用的制作能力。分镜或文字提纲的完成不等于已生成视频或演示文件。
