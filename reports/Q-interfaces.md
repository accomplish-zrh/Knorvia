# Q chat queue owner / integration contract (implementation in progress)

New feature, outside original60/remaining39 counts. Queue belongs to the existing Rust ProductStore + ControlPlane, not a renderer or second executor.

- WAL projection kind `MessageQueue`, checkpoint kind mapping `MessageQueue`; path `<Home>/state/product/message-queues/<threadId>.json`. Existing store mutation→journal locks and WAL write/repair semantics apply. Include this directory AND existing store WAL/checkpoints in C09 backup. No extra background writer or external runtime exists.
- `turnQueue/enqueue {threadId, requestId, idempotencyKey: requestId+'-enqueue', input, options:{model,reasoningEffort,cwd,write,providerId}}` durably accepts. One permanent enqueue identity per message. Return is queue snapshot; `queued` is not model delivery.
- `turnQueue/read {threadId}` returns `{threadId,workspaceId,revision,nextSequence,paused,reason,afterTurnId,afterExecutionId,items}`. Each item stores immutable input/options/provider stamp, id/sequence, status, dispatch method/params, native turn/execution receipt. No credentials.
- `turnQueue/cancel {threadId,revision,messageId}` only cancels `queued`; `dispatching/needs_check/delivered` are not retractable. Pause/resume similarly require queue revision. UI uses independent idempotency keys for controls.
- `ControlPlane::dispatch_queued_messages()` is called from both existing stdio/shared-server owner loops; runs at most every250ms and processes at most4 bounded queue files, one admission each. It calls the existing handle_request→turn/start (or goal/run) under stable frozen idempotency parameters. Do not launch another consumer in A19 or desktop.
- Queue pump checks the SAME `admissions_paused` as restart/automation admission. Successful `prepare_restart` prevents queue dispatch; native model calls remain on existing executor. `queued/paused` messages are durable future intents, not live processes: they need not block shutdown/backup after admission closes. `dispatching` calls occur on the same control owner as restart, so restart cannot overtake an active admission handler. Preserve this ordering if A19 moves admission to workers: claims must enter A19's active admission registry and quiescence count, and per-thread FIFO claims must remain single-owner.
- `rpc_turn_interrupt` durably pauses a pending thread queue before sending interrupt, even if the named turn completed just before this call. If pause WAL fails, interrupt does not proceed. No dequeue side effect runs between these operations on the sole reader.
- Goal queue waits for a bound CURRENT GoalExecution run to be durable completed, plus no active thread turn. It calls existing goal/run with stable requestKey and current active Goal revision; paused/blocked/terminal Goals are never resumed implicitly. Automatic Goal round continuation keeps its owner priority.
- Queue bounds:32 pending/thread,512KiB pending input/thread,128KiB/item,128 queue threads/Home; bounded visible past receipts. Native enqueue idempotency ledger retains old identities after visible receipt pruning.
- Provider stamp hashes the native configured provider/model/account environment; never expose raw keys. Changed configuration pauses old messages rather than rerouting them. Model/effort/cwd/write are frozen at enqueue.
- Recovered dispatching replays original native operation key/params. Unknown native outcome→needs_check and durable queue pause. No same-text receipt guesses or new identity retries.
