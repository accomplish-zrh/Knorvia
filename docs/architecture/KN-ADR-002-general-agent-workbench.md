# KN-ADR-002 — 通用 Agent 工作台改革

日期：2026-09-05。状态：本轮已实现并验收。依据：本次用户最新授权。

## 产品决定

Knorvia 的默认产品是通用任务工作台。新任务、项目、任务历史、成果、扩展和设置构成主导航。一个任务对应一个可恢复的 Kernel Thread；执行、审批、取消与补充输入沿同一原生协议推进。用户切换任务不会中断后台执行。

学习、创作、课堂、书籍、图像/视频工作室不再支配首页、导航、聊天状态或默认启动。旧页面和用户资料保留为迁移来源；只有实际可发现、可运行的能力才能呈现在扩展目录中。不为了保留旧页面继续扩大 StreamEvent 或 Python 主循环。

本决定替代旧总纲中对一级导航、领域功能对等和固定实施顺序的要求。用户明确授权执行者修改这些标准；完整 Codex 派生内核、独立 Knorvia 数据空间、真实执行、用户数据保护和诚实验收继续保留。

## 本轮可验收结果

1. 默认打开独立的原生工作台，不加载旧 UnifiedChatProvider 和领域启动流程。
2. 项目可持久创建、编辑标题和工作目录；任务可新建、续接、重命名、分叉和归档，任务上下文由 Rust 内核续接。
3. 模型与工作目录真实传给回合；实时消息、工具动作、审批、取消、失败和恢复清楚显示。
4. 可将结果保存为有版本的成果，读取内容，并从任务活动中查看证据。
5. 快照与通知共同恢复界面，持久化故障不伪造完成；补充输入和分叉以真实 Kernel 语义实现。
6. 通过 TypeScript/生产构建、相关 Rust/Node 行为测试、实际浏览器交互与本地 scripted Responses 端到端验收；本地夹具不代表线上供应商验收。
7. 采用用户提供的 K 图标原图，完成工作台、网页 favicon、Apple Touch Icon 和 Windows ICO 资源接入。

## 执行组织

主代理负责产品架构、原生界面、跨层验收。三个 gpt-5.6-terra / max 子代理分别负责持久化、原生任务控制、桌面和浏览器协议接入。既有未提交改动在原工作树上保留；没有生产数据删除、凭据迁移、发布或安装器授权推断。

## 完成边界

本轮完成意味着上述改革得到代码和验证支持，不意味着已复刻 Codex 全部功能、完成所有供应商兼容、自动化调度、完整插件生命周期或跨平台安装发行。未覆盖项在验收报告中列出，后续沿同一架构续建。
