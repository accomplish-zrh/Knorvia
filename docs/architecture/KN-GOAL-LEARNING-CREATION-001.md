# KN-GOAL-LEARNING-CREATION-001 — 学习与创作领域增强

日期：2026-09-13。状态：实现及领域验收通过。用户授权：增强 Knorvia 学习与创作能力，查阅 GitHub，自主设定 Goal；全部完成后提交本地版本并推送至现有 GitHub 仓库。发布核对以最终交付消息和 Git 记录为准。

## 产品目标

让用户沿着“选择资料 → 有依据的练习 → 作答反馈与复习 → 创作简报 → 作品评审”继续工作。沿用 ADR-002 的通用工作台，领域入口位于资料库、已有学习页、工作方案与内置技能。资料和领域记录归现有版本化资料库，任务执行仍由单一 Kernel 负责。

## 本轮验收条件

1. 逐题练习固定题库版本；开始与读取不提前返回答案、解释或包含答案的引用。选择题由工具根据提交的选项判分，开放题记录回答并明确自评性质。
2. 同一创建或作答编号重试不会重复写入，不同内容冒用同编号被拒绝；重启后可以从已保存记录继续，未作答不能伪造完成。
3. 错题与到期队列来自逐题作答记录，以实际作答时间计算间隔；来源更新与统计覆盖不足可见。本轮采用可解释间隔规则，不宣称已经集成 FSRS 或通过学习效果试验。
4. 创作简报保存受众、目标、格式、来源主张、内容结构和评审条件。引用必须匹配固定版本的实际原文行号，主观评审注明提供者。
5. 作品评审必须关联真实、非空成果并覆盖全部条件；资料或成果更新后提示复核。写入失败、条件未达成或成果缺失不能返回当前可交付。
6. 资料库可进入学习；已有工作方案提供六个中英文学习与创作预设，能填变量、预览并应用为草稿，不直接执行，不占个人方案存储容量。
7. 内置技能、原生界面、MCP、创作 CLI 使用相同工具实现，打包清单包含新增运行模块。相关行为测试、类型检查和浏览器交互通过；本机模型夹具如实标注。
8. 验收记录和本次代码集成回当前源码，保护已有未提交工作；检查待公开文件，提交并推送到 origin，核对远端提交哈希。不将源码交付表述为已更新安装包或已经验证线上模型。

## 当前代码审计依据

`desktop/learning-pack.js` 已有讲义、题库、整卷尝试与课题级复习；`LearningWorkspace.tsx` 只支持整卷选择题，而且完整答案随题库读取到浏览器。学习页缺少资料库入口。`TaskRecipeMenu.tsx` 已有可复用的草稿预览、变量和 Goal 条件，但初始目录为空。

因此本轮优先补齐可持续使用的领域流程、真实记录和现有入口。模型生成的教学准确性、长期学习效果、视频成片质量和供应商可用性，不能由这些确定性行为检查替代。

## 实现与验证记录

- 逐题练习：独立保存固定版本题库、作答与自评，支持并发写入冲突恢复、同编号重试、刷新后继续。开始与读取只返回当前题目，作答后才返回本题解释和原文证据。开放题先保存原话，再记录用户明确提供的自评。
- 复习：由已保存的逐题记录计算 1/2/4/8… 天间隔（上限 30 天），答错后次日到期。对当前题库、已更新题库和已移除题库区分显示；旧版成绩不混入新版题库。超过 200 份练习会话时明确报告统计不完整。
- 创作：简报固定来源及可选学习成果，引用逐行校验。评审要求非空的真实作品版本和完整条件覆盖，并记录评审者。资料、学习成果或作品变化后，原通过结果转为需要复核。
- 入口：资料库的文本资料菜单进入学习；工作方案包含导学、错题复习、教回练习、创作简报、资料转文章和视频分镜。个人副本可编辑；内置项不占个人方案容量。套用方案只填草稿，已有任务不会因此创建 Goal 或开始执行。
